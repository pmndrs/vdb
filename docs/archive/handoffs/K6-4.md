# K6.4 handoff: spectral media in the core frame renderer

Design: [K6-core-renderer.md](../../dev/design/K6-core-renderer.md) §3.3–§3.4 (spectral: pipeline key, stacked targets,
alpha prefix), D34. Builds on [K6-2.md](./K6-2.md), [K6-2b.md](./K6-2b.md), [K6-3.md](./K6-3.md), [K6-5.md](./K6-5.md),
[K6-5b.md](./K6-5b.md) and the TSL reference of [K3-5.md](./K3-5.md) (his spectral port; the twins in
`tools/frame/spectral.ts`).

**Landed:** `settings.spectral` in the core for both lightings: a `spectral` pipeline key on every kernel with a spectral
variant (gather 'volume' and 'frame', shadow grid, transmittance, environment grid, resolve, composite, volume shadow
maps), CPU twins, probes with fail-before mutations, and `./three` `backend: 'core'` with `spectral: true` (the core's
"spectral is K6.4" warning is gone). The emission light (probes) stays grey, as his `FrameEmissionLight` (no spectral
branch); volume emission inside the spectral gathers works per channel.

## Design changes (please review)

1. **One transmittance dispatch for every slot group** (his one pass per group; the design said one dispatch per group):
   the group is gid.z / (R · count), so no per-dispatch uniform and one pipeline.
2. **The shadow grid is two textures with one layout** (design: "2 stacks"), so the absorption shares the extinction's
   origins; partials are 3 words per voxel.
3. **The spectral history is one texture twice as deep** (scatter and alpha halves) so the resolve stays at 3 storage
   textures (the default limit is 4).
4. **Spectral volume shadow maps are two textures** (grey map + `rgbTexture`), not extra layers (the design's "+ spectral
   layers"): a cube view takes exactly 6 layers.
5. **The alpha prefix** is rg16float with `texture-formats-tier1`, else rgba16float (written directly; the K7.3
   buffer-and-copy trick is not needed: the resolve writes one texel per froxel either way).
6. **`render()` with spectral needs `targets.sceneColor`** and draws without blending.
