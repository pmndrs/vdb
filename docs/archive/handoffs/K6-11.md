The two failures (both `ambientOcclusion` being on by default, not a defect in the kernels):

1. `k3-frame-scattering` "K3.4 defaults (V33)": the in-page repeat of a static, un-jittered 'frame' + temporal + 'neural' scene
   is no longer byte-identical: frame 2 differs from frame 1 in **2 bytes by 1/255** (0 with `&ao=0`; with `jitter` off the
   ring phase is 0, so it is a blend rounding step, not noise). The spec now accepts ≤ 1/255 on < 0.1 % of bytes (the harness
   reports `inPageDiff`); two page loads stay byte-identical (unchanged assertion).
2. `k3-frame-lighting` "K3.3 temporal reprojection + jitter": its gate compares the temporal frames with the mean of the
   un-accumulated jittered frames. With AO on, jitter + temporal turn the ambient ring per frame (K6.Q1a, by design), so the
   temporal frames converge to the ring-averaged ambient, not to the fixed-ring mean: PSNR vs that mean 51.3 dB (a single frame:
   56.9), against 62.0 vs 57.0 dB with AO off (frame-to-frame change 0.21 → 0.09 with AO on, 0.21 → 0.03 off). The query got `&ao=0`
   (the gate is about the froxel history); the ring's accumulation is the k6-ambient `aoJitter` probe's. **Open question for the
   owner:** is the AO ring's frame-to-frame noise acceptable as a default with `temporal` on (the temporal blend cuts it to
   ~0.09 / 255 per channel on this scene), or should `ambientOcclusion` keep the ring fixed? Test: the K3.3 numbers above
   (`k3-frame ?lighting=frame&lights=dir-hemi&temporalCheck=16&ao=0|1`).

  `e2e/k6-frames.spec.ts` so the AO default is covered by the before/after gate (today only the `'outward'` environment frame moves).
