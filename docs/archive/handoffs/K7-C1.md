# K7.C1 + K7.H1 handoff (2026-11-28)

`writeNvdb({ codec: 'blosc' })` (K7.C1) and the Half follow-ups (K7.H1). Along the way: K4.12's root order was wrong
and is reverted, so our NanoVDB images now equal native ones byte for byte past GridData.

## What changed

**K7.C1, Blosc writer (DIVERGES V164, THIRD_PARTY).**
- `tools/vdb/lz4.ts`: `compressLz4Block`, a port of LZ4 1.9.4 `LZ4_compress_generic` (the copy OpenVDB v14.0.0 vendors;
  BSD-2) for the one case Blosc uses: one block, no dictionary, 64-bit hashing (`LZ4_hash4` with a 2^13 u16 table under
  64 KiB + 11 bytes, `LZ4_hash5` with a 2^12 u32 table above; the 40-bit product is done in 32-bit halves, no BigInt).
  Same skip schedule, catch-up and conservative `limitedOutput` checks, so it gives up exactly where native does.
- `tools/vdb/blosc-write.ts`: `compressBlosc`, a port of the compress half of `vdb_blosc.c` (c-blosc 1.21.6 cut to LZ4;
  BSD-3): block size rule, splits, byte shuffle, per-split `maxout`, raw splits, the memcpy fallback.
- `writeNvdb` codec `'blosc'` (`nvdbBloscPayload`: 1 GiB chunks, `destSize = chunk + 16`, as `io::Internal::write`);
  `vdbBakeCoarseFirst` and `scripts/bake-coarse-first.mjs` take it too. No new dependency.
- Internals (`tools/internal.ts`): `compressBlosc`, `shuffleBytes`, `compressLz4Block`, `lz4CompressBound`,
  `nvdbBloscPayload`, `NVDB_BLOSC_CHUNK_BYTES`. Public API: only the `codec` union widened (export lists unchanged).

**Root order (found by the native read check).** v14's `nanovdb_validate` failed every grid we built with negative
coordinates and several upper nodes ("Upper node is not stored breadth-first"). K4.12 sorted the root table by unsigned
key while the upper nodes stayed in signed origin order. Native (a532de55 and v14 `nanovdb_convert`, e.g. the cube)
uses signed origin order for both: `tree.ts` does again. That was also TASKS K7.H1 (c) ("v14 orders root tiles
differently"): it was our bug.

**K7.H1.**
- (a) `stats.ts`: GridStats' f64 Welford (`Stats<T,0>::add(val)`, `add(val, n)`, `add(other)`, operation order as in
  C++) is the default; `'sums'` stays internal (`vdbSetStatsAccumulation`) for the A/B. `tree.ts` merges children in slot
  order (was Map insertion order). Min/max are stored as GridStats' `Extrema` leaves them: a node of only +∞ keeps the
  type's largest finite value as min (FLT_MAX, or 0x7BFF for Half). DIVERGES V73 closed.
- (b) Half sources: `quantize.ts` reads Float or Half (exact widening); new mode `vdbQuantize(…, 'float')`;
  `vdbCollapseGrid` keeps Half; `transformLeafValues` and core `vdbApplyValueTransform` take Half (f32, then nearest half).
  Fp* sources still throw `VDB_UNSUPPORTED_GRID_TYPE`.

## Evidence (Apple M5 Pro, local OpenVDB/NanoVDB v14.0.0 build in the lead scratchpad `native/prefix`, no Docker)

- **Frames byte-identical to native `nanovdb_blosc`:** 170 corpus inputs (sizes 0 to 3 MiB + 1000 around every rule edge,
  zeros/random/float ramps/sparse floats/runs/text/periods 1000, 65535 and 70000 bytes, NanoVDB images; typesize 1, 2, 4,
  8, 16, 17; shuffle off; clevel 0, 1, 3, 5, 8, 9; auto and forced blocks; tight `destSize`s) and four output-budget
  sweeps (every `destSize` 0 to n + 16 for three 3000-byte inputs, 441 sizes around the unlimited size of a 66,000-byte
  32-bit-table input): 9,492 frames, every one equal, native decodes every frame of ours (`blosc-write.test.ts` with
  `VDB_NATIVE_BLOSC_FRAMES`; hashes committed in `fixtures/native-v14/blosc-frames.json` so CI checks without native).
- **Whole files:** `nanovdb_convert -b` of cube, smoke, sphere and utahteapot (16.6, 6.9, 5.4, 79 MB images; the teapot
  is 78 Blosc blocks) vs `writeNvdb(images, { codec: 'blosc' })` of the same images: byte-equal except FileHeader/FileMetaData
  version and FileMetaData nameKey (we write 0, as for NONE/ZIP). Committed fixtures `sphere_fog_blosc.nvdb` and
  `two_grids_blosc.nvdb` the same (unit test).
- **Native reads ours:** `nanovdb_validate -v` + `nanovdb_print -l` pass on our BLOSC files of 13 Float/Fp8/Half grids
  and an 8-grid segment. FpN fails `nanovdb_validate` ("Leaf node is not stored breadth-first") exactly as native's own
  FpN primitives do (the validator steps leaves by a fixed size); `nanovdb_print` reads them.
- **Sizes (KiB, NONE / ZIP-9 / BLOSC):** smoke Float 6857 / 2710 / 3011; sphere 5416 / 639 / 840; teapot 79041 / 18215
  / 20888; cube 16641 / 132 / 140; sphere_fog primitive 4028 / 219 / 442. BLOSC is 1.06 to 2.55 times ZIP; it is the
  faster codec natively, not the smaller one.
- **Stats A/B** (`scripts/ab-stats-accumulation.mjs`, 103,448 ave/stddev values over half_edge, three v14 Half
  primitives, three a532 Float primitives, four parity samples): Welford 0 differ; sums 44 differ (1 ulp, or ±∞ where
  native has NaN). With Welford and the root order, `buildFromVdb` of the four samples equals native a532 and v14 images
  past GridData, and `vdbQuantize(float, 'half')` of the primitives equals native v14 Half images but for the root
  background (`effectiveBackground`, by design).
- **Fail-before mutations** (each makes a test fail; script `scratchpad/formats-k7c1/mutate.py`): LZ4 skip trigger,
  hash5 carry, small-table hash shift, Blosc split enlargement, Blosc acceleration, `writeNvdb` codec id, chunk
  `destSize`, unsigned root order, `'sums'` default, merge product order, child merge order, extrema start, Half source
  stride, Half collapse codec, Half transform path, `vdbApplyValueTransform` Half gate. One survivor: loosening LZ4's
  literal budget check never changes an outcome (the match check that follows always fires too; in C it guards memory).
  Recorded in V164.
