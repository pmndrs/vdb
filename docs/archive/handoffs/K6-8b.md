## K6.8b: the emission light through the core

**Outcome.** The TSL port of the probe lookup is gone. `three/frame/emission-light.ts` now runs the core's own
`vdbEmissionIrradiance(probes, smp, grid, world, normal)` from `vdbEmissionProbeWgsl()` through a `wgslFn`. This is the
pattern K6.8a used for the mesh-shadow receivers:
- **`probes`:** a `texture3D` node over a 3D `ExternalTexture` stand-in of the core's probe stack, with `sampler(node)`.
- **`grid`:** the core's `VdbEmissionGrid` buffer, bound through `vdbThreeStorageStandIn` as `array<vec4u>`. A
  generated loader unpacks it. The loader now lives in `three/frame/core-structs.ts`
  (`vdbFrameStructLoaderWgsl`, `VDBFrameStructLoaderNode`) and serves the shadow view too.
- **Core change:** one line. `outputs.emissionProbes.grid` gains `STORAGE` usage.
- **Gone:** the per-light uniform copies of the cascades, the centre, the stack origins and the stack size. The receiver
  reads them from the core's buffer.

**Frames.** The `k6-frames` emission cases (`shadows-case-emission-source-dense` / `-sparse`, `rgba` and `rgbaOff`) are
byte-identical to the TSL port. three r187 made the WGSL route possible and not worse.

**Finding-8 class: reproduced, fixed.**
- **Reproduction:** `k3-frame-shadows ?case=emission&emitter=blob&mutate=probes`. It halves `resolution` for four
  renders, then puts it back. On `2a1ac7b` this gave 4 uncaptured errors (`Destroyed texture [Texture "vdb three frame
  emission probes"] used in a submit`). The frame after the restore differed from the first (max 2/255).
- **Cause:** the receiver is a `MeshLambertMaterial`. three gives it SHARED refreshes, which never re-read a texture
  node's `value` swap.
- **Not reproduced:** `mutate=light` (the light hidden: the core releases the stack) and `mutate=emitter` (the volume
  hidden) passed before the fix. Hiding the light changes the lights, so the receivers rebuild anyway. With the volume
  hidden, the core keeps its stack.

**The fix.**
- **One shared set of nodes.** The light node makes its texture node, storage node and `wgslFn` once, at its first
  receiver build.
- **Placeholders.** While the core has no probes, the nodes bind a 1³ texture and a zero grid. With `info.x` 0 the
  receiver returns 0 without sampling, the same as the TSL port's `gridCount` 0.
- **New core objects.** When the core makes a new stack or grid (a new resolution, a released stack, another frame
  renderer, the frame renderer disposed), the nodes get new stand-ins and the node sets `needsUpdate = true`.
- **Why `castShadow`.** three r187's `LightsNode.customCacheKey` holds a light node's version only for a `castShadow`
  light. So `VDBFrameEmissionLight.castShadow` is now always `true` through an accessor. The light casts no shadow: its
  node overrides `setup`, and `Light` has no `shadow`, so the observer skips it.
- **Timing.** The receivers rebuild at their next render. The current render still draws the old stack, which the core
  keeps alive for two more updates and a task.
- **Self-test.** The internal-1 self-test (`vdbFrameCheckLightReset`) now also checks that the lights cache key follows a
  `castShadow` light's node version.
- **One renderer.** A light's receivers belong to one renderer. Building them from a second renderer throws.

**Guards.**

| Guard | Result |
|---|---|
| `k6-shadows` "K6.8b the emission light, probe stack {probes, light, emitter} away and back" | No uncaptured error. The frame after equals the first. Fail-before: `probes` on `2a1ac7b` (above). A mutation that sets `castShadow` false brings the 4 errors back. |
| Unit: the cache-key self-test (fail-before: a `customCacheKey` without the version throws `VDB_ENGINE_MISMATCH`) | Pass |
| Unit: `castShadow` stays on (it survives a set and a `copy`) | Pass |
| Unit: the grid loader reads each of the 22 words once | Pass |

## K6.10b: tests for the gate review's gaps

Each test below compares the GPU result with its CPU twin. Each mutation must then fail it.

**Composite** (`k6-core ?probe=integrate`). New query parameters:
- `srgb=1`: the scene colour sits in the target; the twin is `vdbFrameSrgbBlend`.
- `depthMode=ortho|reversed|ortho-reversed`: the scene depth's projection. Its twin is the new tools function
  `vdbFrameSceneViewDepth` (internal, not public).
- `depthFormat=depth32float`: the depth is written by a pass that sets `frag_depth`, then read as `texture_depth_2d`.

Mutations (all WGSL patches, `k6-core.ts` `WGSL_PATCHES`):
- `wgsl-composite-srgb`: no OETF on the scene colour.
- `wgsl-composite-ortho`: the orthographic flag ignored.
- `wgsl-composite-reversed`: the reversed flag ignored.
- `wgsl-composite-depth`: the depth read one pixel to the right.

| Probe | Twin (1120 values each) | Mutations: values over the bar |
|---|---|---|
| grey sRGB | max 0.50 ulp, 0 over | `wgsl-composite-srgb` 1114; `coverage` 318 |
| orthographic | 0.50 ulp, 0 over | `wgsl-composite-ortho` 1048 |
| reversed perspective | 0.50 ulp, 0 over | `wgsl-composite-reversed` 1114 |
| `depth32float` | 0.50 ulp, 0 over | `wgsl-composite-depth` 878 |
| reversed orthographic, `depth32float`, sRGB | 0.50 ulp, 0 over | ortho 1048, reversed 758, depth 861, srgb 1114 |

**Resolve under camera motion** (`?probe=resolve&move=1`).
- **Setup:** the previous camera is turned and stepped back a little. The history is then read between texels: the twin
  uses `vdbFrameTexture3DLinear` with the kernel's clamps.
- **Blend:** the motion blend now varies per froxel, so `resolveTwin` gains `blendAt`.
- **Coverage:** 1680 / 1680 froxels with history have a blend below 1 and are read off a texel centre.
- **Twin:** 9240 values, max 0.52 ulp, 0 over.
- **Mutations:**
  - `wgsl-resolve-reproject` (the turn ignored in x, y): 3639 over.
  - `wgsl-resolve-motion` (gain 2 instead of 4): 3639 over.
  - `temporal-clamp`: 2857 over.

**Emission colour inside the 'volume' gathers** (`?probe=gather&emissionColor=lut|hook`).
- **Setup:** volume B gets a synthetic LUT row (f32, not white) or a user hook. The twin's `emissionAt` takes the volume's
  colour (`TwinVolume.emissionColor`).
- **Dense needs `groups=2`:** with `groups=1`, the dense probe gives both volumes volume A's source, which has no emission
  channel.
- **Mutations:** `wgsl-emission-lut` (the lower LUT texel's channels turned), `wgsl-emission-hook` (the hook result
  swizzled), and `emission-color` (the twin draws white).

| Probe | Twin (4608 values each) | Mutations: values over the bar |
|---|---|---|
| dense, LUT | max 1.45 ulp, 0 over | `wgsl-emission-lut` 311, `emission-color` 325 |
| sparse, hook | 2.09 ulp, 0 over | `wgsl-emission-hook` 157, `emission-color` 157 |
| spectral, LUT | 1.41 ulp, 0 over | `wgsl-emission-lut` 312 |

**Orthographic level-set pass** (`k3-levelset ?scene=teapot&twin=1&backend=core&ortho=1`).
- **Setup:** an orthographic camera with his camera's pose and framing. The pass detects it from the projection. The
  twin traces orthographic rays.
- **Result:** IoU 1.0 (1236 / 1236 px), hit max 2.5e-3 voxels, normal p99 4.4e-4°, depth max 1.3e-8, shade max 1.0e-7.
- **Mutations:**
  - `wgsl-ls-ortho` (the pass ignores its flag): IoU 0.397, hit max 647 voxels.
  - `ray-ortho` (the twin traces perspective rays): IoU 0.061.

where the textures were destroyed at once.

## Follow-ups

- **Owner items, untouched:** delete `froxelMix: 'over'`; deprecate `vdbVolumeNodes` / `vdbVolumeUniforms`; the K6.10a
  naming proposal.
- **'frame' gathers:** the emission colour LUT and hook are probed in the 'volume' gathers only. The 'frame' gather
  probe's twin (his lighting twins) still draws white emission; extend `?probe=frame` the same way.
- **Hardware:** run the new k6-core probes on hardware (`scripts/k6/k6-core-hardware.mjs`). The moving-camera resolve
  relies on SwiftShader's full-precision filtering.
- **One renderer per light:** `VDBFrameEmissionLight` throws when a second renderer builds its receivers. Make the nodes
  per renderer if a host renders one scene with two renderers.
- **Scratchpad clash:** this task first unpacked its baseline into the shared scratchpad's `base/`, which an earlier
  agent had used (K6.8a era, idle). Those files now hold `2a1ac7b`. The baseline that was used is `k68b-base/`.
