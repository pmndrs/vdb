## Follow-ups

- **Sources as thin wrappers** (§6): `vdbSparseSource` / `vdbDenseTextures` still carry their TSL nodes and the TSL GPU
  pyramid (only built when a custom material samples them). A slimmer handle (pool, ids, options, stats) for the frame
  renderer, with the TSL part split off for `vdbVolumeNodes` users, would drop ~1,000 lines; it changes the K3.2 harnesses
  (`k3-sparse`, `k3-pyramid`, `wvdb-sampling`) and is its own task.
- **`froxelMix: 'over'`** (§2.2 said K6.8 deletes the loser): kept. Deleting it removes gather variants and the 'over' twin
  probes; K6.R decided 'mixture' as the default, the owner can retire 'over' with that change.
- **Receivers through the WGSL** (§6): the mesh-shadow receiver and the emission light stay TSL ports of
  `vdbVolumeShadow` / `vdbEmissionIrradiance` (the K6.5 code, unchanged maths). Binding the map's `view` uniform buffer into
  three (a buffer stand-in like `VDBGridNode`'s) would let them call the WGSL itself.
- **Per-kernel timing**: `passHook` brackets the whole update; per-kernel timestamps (one pair per compute pass the update
  opens) are a K6.T item.
- **MLP builder in the public API**: `VDBFrameMlp` is public (experimental) but `vdbFrameMlpFromNeural` /
  `vdbFrameNeuralWeights` are tools internals; a host that wants his weights back after assigning another network has to
  keep the original object (`renderer.mlp` before the change).
- **Grid size**: the new `shadowResolution` clamp keeps a frame from being lost; a stack split into ≤ 256 MiB textures
  (or `maxBufferSize` in the device request, documented) would allow 256³.
- **`silhouette-check.mjs`** (K6.3a, core vs TSL) is retired; its numbers stay in K6-3a.md. A core-only V80 check against
  his captures could come back with K6.R (the report's `v80-*` groups now report core rows only).
- **demo 06 golden** is a Linux snapshot; it fails on macOS hosts (text). Not K6.8's; CI runs Linux.
- TASKS.md / PHASES.md / DIVERGES.md (not edited here): mark K6.8 done, close K3.8; rows V138–V143 below.
