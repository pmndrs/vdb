## What was deleted and what stayed

`packages/vdb/src/three/frame`: **11,094 → 2,605 lines** (`git diff --shortstat 1376cfc..HEAD -- packages/vdb/src/three`:
597 insertions, 9,768 deletions). Deleted: `chunks.ts`, `inject-material.ts`, `integrate-material.ts`, `density-material.ts`,
`lighting-material.ts`, `shadow-density-material.ts`, `transmittance-material.ts`, `temporal-material.ts`,
`environment-material.ts`, `environment-grid-material.ts`, `grid-mip-material.ts`, `volume-shadow-material.ts`, `neural.ts`,
`phase.ts`, `layout.ts`, `view.ts`, `lights.ts`, `blackbody.ts` (the TSL hook), and the TSL halves of `renderer.ts`,
`volume-shadows.ts` and `emission-light.ts`.

| File | Lines | What it is now |
|---|---|---|
| `renderer.ts` | 504 | `VDBFrameRenderer`: one core renderer per device; the first proxy (or receiver / emission light `updateBefore`) of a render collects volumes, converts lights, passes `scene.environment` and three's shadow maps, records `core.update()` into its own encoder and submits; `passHook`, `froxels`, `mlp`, `core`, `redrawStats` |
| `volume.ts` | 408 | `VDBFrameVolume`: his props (copied into the core's `VDBFrameVolumeParams` each render), the box (`boxMatrix`), `setMedium`, `getPhase` |
| `volume-shadows.ts` | 459 | `VDBFrameVolumeShadowReceivers` (internal): the `filterNode` install (V60) and the receiver node reading the core's maps with their drawn state (the former `setupCore`, unchanged maths) |
| `emission-light.ts` | 319 | `VDBFrameEmissionLight` + its `AnalyticLightNode` reading the core's probe stack |
| `core-environment.ts`, `core-occluders.ts`, `core-textures.ts`, `core-integrate-material.ts` | 669 | as K6.1–K6.5b (the env material base is inlined) |
| `three-internals.ts`, `medium.ts`, `spectrum.ts`, `index.ts` | 246 | |

Stayed outside `three/frame`: `VDBVolumeMaterial`, `VDBLevelSetMaterial`, `VDBPoints`, `VDBGridNode`, and the source
handles `vdbDenseTextures` / `vdbSparseSource` with `vdbVolumeNodes` / `vdbVolumeUniforms`. The sources stay as they were
(not reduced to thin wrappers): `VDBFrameRenderer` reads their volume / pool, ids, boxes, options and stats into the core's
own sources (`vdbDenseSource`, `vdbSparseSourceGpu`), and their TSL nodes and GPU pyramid run only when a custom material
samples them. Reducing them is a follow-up (below).
