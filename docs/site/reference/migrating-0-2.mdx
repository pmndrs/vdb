In 0.2.0 the froxel renderer moved into the core: `@pmndrs/vdb` draws every frame with WGSL compute kernels
(`vdbCreateFrameRenderer`, see [Rendering without three](/core/rendering-without-three)), and `@pmndrs/vdb/three`'s
`VDBFrameRenderer` is a thin adapter over it. The TSL pass materials, their shader chunks and the internal `backend`
switch are gone. Frames match 0.1's TSL path closely (57–70 dB on mjurczyk's scenes in the K6 A/Bs; the `'outward'`
environment irradiance, about 47 dB, differs most), and volume silhouettes can differ by a pixel. The full list is in the [changelog](https://github.com/pmndrs/vdb/blob/main/packages/vdb/CHANGELOG.md).

Beyond the froxel renderer, 0.2 only renames the core's GPU names (below) and takes three helpers out of the tools'
public API. `VDBGridPool`, `VDBGridNode`, `VDBVolumeMaterial`, the level sets and the points keep their 0.1 API.

## Core names lose the `Gpu` suffix

The GPU is the default, so a name carries no `Gpu`; a `Cpu` suffix marks the CPU twin of a GPU function. `@pmndrs/vdb`
(the core) and `@pmndrs/vdb/three` can now export one name each (`vdbGridStats`, `vdbDecodeToAtlas`, `vdbSparseSource`,
`VDBFrameRenderer`, `VDBFrameVolume`, `VDBSparseLod`, `VDBSparseSourceOptions`): the core's takes a `GPUDevice` and an
encoder, the `./three` one a three renderer or object. Import by path; alias when you use both
(`import { VDBFrameRenderer as VDBCoreFrameRenderer } from '@pmndrs/vdb'`).

| 0.1 / pre-release (`@pmndrs/vdb`) | 0.2 (`@pmndrs/vdb`) |
|---|---|
| `vdbGridStatsGpu` | `vdbGridStats` |
| `vdbDecodeToAtlasGpu` | `vdbDecodeToAtlas` |
| `VDBBoxPyramidGpu`, `VDBBoxPyramidGpuOptions` | `VDBBoxPyramid`, `VDBBoxPyramidOptions` |
| `vdbSparseSourceGpu`, `VDBSparseSourceGpu`, `VDBSparseSourceGpuOptions` | `vdbSparseSource`, `VDBSparseSource`, `VDBSparseSourceOptions` |
| `VDBSparseVolumeGpu`, `VDBSparseVolumeGpuOptions`, `VDBSparseLodGpu` | `VDBSparseVolume`, `VDBSparseVolumeOptions`, `VDBSparseLod` |
| `VDBFrameRendererGpu`, `VDBFrameRendererGpuOptions`, `VDBFrameVolumeGpu` | `VDBFrameRenderer`, `VDBFrameRendererOptions`, `VDBFrameVolume` |
| `vdbCreateLevelSetPassGpu`, `VDBLevelSetPassGpu`, `VDBLevelSetPassGpuOptions` | `vdbCreateLevelSetPass`, `VDBLevelSetPass`, `VDBLevelSetPassOptions` |
| `vdbCreatePointPassGpu`, `VDBPointPassGpu`, `VDBPointPassGpuOptions` | `vdbCreatePointPass`, `VDBPointPass`, `VDBPointPassOptions` |
| `VDBFrameRendererGpu` (type, from `@pmndrs/vdb/three`) | removed: it would collide with the `./three` class. `frameRenderer.core` is typed by the core's `VDBFrameRenderer` |
| `VDBFrameLoader` (core and `./three`) | `VDBSequenceFrameLoader` |
| `wvdbPrefixLength`, `nvdbResponseLength`, `vdbMakeFpNLeafCodec` (`@pmndrs/vdb/tools`) | not public API (`tools/internal`) |
| `vdbSampleTrilinear`, `vdbSampleNearest`, `vdbSampleTrilinearVec3` (`@pmndrs/vdb/tools`) | `vdbSampleTrilinearCpu`, `vdbSampleNearestCpu`, `vdbSampleTrilinearVec3Cpu` |
| `vdbReadValueF32`, `vdbReadValueVec3` (`@pmndrs/vdb/tools`) | `vdbReadValueF32Cpu`, `vdbReadValueVec3Cpu` |

## Removed names

| 0.1 (`@pmndrs/vdb/three`) | 0.2 |
|---|---|
| `VDBFrameRendererSettings` | `VDBFrameSettings` (the core's, re-exported). It adds `occlusion`, `multiScaleLevels`, `ambientOcclusion`, `ambientOcclusionPairs` and `ambientOcclusionSteps` |
| `VDBFramePhase` | `VDBFramePhaseName` |
| `VDBFrameMultipleScattering` | `VDBFrameMultipleScatteringMode` |
| `vdbFrameLights`, `vdbFrameAllLights` | `VDB_FRAME_LIGHT_BITS` (`ambient`, `point`, `directional`, `spot`, `hemisphere`, `environment`), `VDB_FRAME_ALL_LIGHTS` |
| `vdbFrameBlackbodyEmission(spectrum, exponent)`, `VDBFrameBlackbodyHook` | `emissionColor: { spectrum, exponent }` (a `VDBEmissionColor`: `'white'`, `{ spectrum: 'planck' \| 'soot', exponent? }`, `{ lut }` or `{ wgsl }`). A TSL hook throws `VDB_BAD_OPTION` |
| `VDBFramePass` | `passHook` is `{ timestampWrites?, begin?(), end?(update) }`: the timestamps bracket each core update (`VDBFrameTimestamps`, `VDBFrameUpdate`) |

## Renamed or removed members

| 0.1 | 0.2 |
|---|---|
| `VDBFrameRenderer.neuralNetwork` | `VDBFrameRenderer.mlp` (`VDBFrameMlp`, EXPERIMENTAL; our trained weights by default; `null` runs `'neural'` / `'mlp'` as 1D diffusion) |
| `VDBFrameRenderer.renderFroxels()`, `holdFroxels` | `VDBFrameRenderer.froxels` (`false` keeps the last froxels) |
| `VDBFrameRenderer.environment`, `environmentLights` (a readback) | none: the core extracts the environment lights on the GPU |
| `VDBFrameRenderer.redrawStats` | the core's `VDBFrameRedrawStats` (adds `volumeShadows`) |
| none | `VDBFrameRenderer.core`: the `VDBFrameRenderer` (core) (its `outputs`), after the first render |
| `VDBFrameVolume.volumes[0].matrix` | `VDBFrameVolume.boxMatrix` |
| `VDBFrameVolume.sourceUniforms`, `volumes`, the pass-material fields | none |
| `vdbVolumeUniforms`, `vdbVolumeNodes`, `VDBVolumeNodes`, `VDBVolumeNodesOptions`, `VDBVolumeUniforms`, `VDBVolumeUniformParameters`, `VDBThreeSourceFactory` | deleted in 0.2.0 (no deprecation cycle). A custom TSL material samples a pooled grid through `VDBGridNode` (`vdbSample`, `vdbReadValue`, the helpers); custom WGSL or compute uses the core's `vdbSparseSource` / `vdbDenseSource` `wgsl()`; the full look is `VDBFrameRenderer` |
| `VDBThreeDenseSource.textures`, `VDBDenseChannelTextures` | none: `vdbDenseTextures(volume)` is a handle with no GPU object (the core's `vdbDenseSource` uploads the texels) |
| `VDBThreeSparseSource.pyramid`, `pyramidBuilds`, `refreshPyramid()`, `nodeAverageFn()`, `skipEmptyFn()`, `createUniforms()`, `createNodes()`, `VDBSparsePyramid`, `VDBSparseVolumeUniforms`; the `pyramidBuild` option | none: the frame renderer's core source builds its own pyramid on the GPU (`pyramidMax` still sizes it). `gpuBytes` is `{ pool }`; nothing calls `refreshStats()` for you now (`VDBFrameRenderer` copies a changed `stats` into its core slot) |
| `froxelMix: 'mixture' \| 'over'` | none: overlapping volumes in a froxel always combine order-independently (the former `'mixture'`). His draw-order "over" blend is deleted |
| `VDBSequence` from `@pmndrs/vdb/three` | the core's `VDBSequence` (`@pmndrs/vdb`); `@pmndrs/vdb/three` re-exports it |

{/* snippet: migrate-0-2 */}
```ts
import { VDB_FRAME_LIGHT_BITS, type VDBFrameRenderer, type VDBFrameSettings, type VDBFrameVolume } from '@pmndrs/vdb/three';

// 0.1: frameRenderer.neuralNetwork = weights;   0.2: the generic MLP data (null: 1D diffusion)
frameRenderer.mlp = null;
// 0.1: frameRenderer.holdFroxels = true;   0.2: false keeps the last froxels
frameRenderer.froxels = false;
// 0.1: vdbFrameBlackbodyEmission('planck', 1.5);   0.2: plain data
volume.emissionColor = { spectrum: 'planck', exponent: 1.5 };
// 0.1: vdbFrameLights.directional | vdbFrameLights.ambient
volume.lights = VDB_FRAME_LIGHT_BITS.directional | VDB_FRAME_LIGHT_BITS.ambient;
// 0.1: VDBFrameRendererSettings;   0.2: the core's VDBFrameSettings
const settings: VDBFrameSettings = frameRenderer.settings;
// the core renderer itself, after the first render (its outputs: shadow maps, emission probes)
console.log(frameRenderer.core?.outputs);
```

## Behaviour to check

- `ambientOcclusion` is **on by default** (4 direction pairs): ambient, hemisphere, light-probe and environment-irradiance
  light is now attenuated by the medium, so scenes with such lights get darker (single scattering was 35 to 148 % too bright
  against a path-traced reference with it off). Frames without those lights do not change. `settings.ambientOcclusion = false`
  restores 0.1's unshadowed ambient exactly.
- `multipleScattering` still defaults to `'neural'` (our network, trained on procedural media; 0.1 shipped his weights). It runs the core's generic MLP, which is
  EXPERIMENTAL: its data shape may change before 1.0.
- Settings out of the device's range clamp with a one-time console warning instead of failing: `shadowResolution`
  (the transmittance stack must fit `maxTextureDimension3D` and `maxBufferSize`) and `castShadowMapSize`.
