`vdbModuleWgsl(options)` returns WGSL text to put in front of your own shader. It is generated per feature set, so
what you do not use compiles out, and every symbol is prefixed `vdb`. The same options always give the same bytes.

{/* snippet: module-options */}
```ts
import { VDB_ALL_SCALAR_TYPES, vdbCheckModule, vdbModuleEntries, vdbModuleWgsl } from '@pmndrs/vdb';
import type { VDBSlotModuleOptions } from '@pmndrs/vdb';

const options: VDBSlotModuleOptions = {
    slot: { group: 0, firstBinding: 0 }, // where the pool is bound: @group(0) @binding(0) var<storage, read> vdbPool
    types: ['float', 'fp8'], // or VDB_ALL_SCALAR_TYPES to never rebuild the pipeline when a new type arrives
    profile: 'march', // 'read' < 'sample' < 'march'; each includes the one before
    helpers: ['cellBoundTrilinear', 'hddaCellEnd'], // opt-in WGSL helpers
};
const wgsl = vdbModuleWgsl(options); // deterministic: the same options give the same bytes
const entries = vdbModuleEntries(options.slot); // the bind group layout entries for that slot

vdbCheckModule(pool, options); // throws VDB_TYPE_NOT_COMPILED if the pool holds a type the module lacks
```

## Binding: slot or buffer

Exactly one of `slot` and `buffer`:

- `slot: { group, firstBinding }` declares `@group(g) @binding(b) var<storage, read> vdbPool: array<u32>`. The same
  `VDBSlot` goes to `vdbModuleEntries(slot)` for the layout and to `pool.bindGroupEntry(slot)` for the bind group.
- `buffer: '<wgsl expression>'` declares nothing and reads your `array<u32>` through that expression. This is how
  engine adapters bind the pool through their own storage node.

{/* snippet: module-buffer */}
```ts
import { vdbModuleWgsl } from '@pmndrs/vdb';

// Buffer mode declares no binding: the module reads the host's `array<u32>` through this expression.
// This is how the three.js adapter binds the pool through three's own storage node.
return vdbModuleWgsl({ buffer: 'vdbPool.value', types: ['float'], profile: 'sample' });
```

## Profiles

Each profile includes the one before it.

| Profile | Adds |
| --- | --- |
| `read` | `vdbAccessorInit`, `vdbReadValue`, `vdbIsActive`, `vdbGridCount`, `vdbGridType`, `vdbIndexMin`, `vdbIndexMax` |
| `sample` | `vdbSample` (trilinear, or `nearest` with `sampler`), `vdbWorldToIndex`, `vdbWorldToIndexDir`, `vdbIndexToWorld`, `vdbIndexToWorldDir`, `vdbRayClip` |
| `march` | the HDDA (`vdbHddaInit`, `vdbHddaUpdate`, `vdbHddaStep`), `vdbGetDim`, `vdbHasStats`, `vdbValueMax`, `vdbNodeMax` |
| `majorant` | `sample` plus `vdbMajorantInit`, `vdbMajorantNext`, `vdbMajorantGlobal` (and `vdbMajorantMinimum` with `minima`); `march` too with `majorant: 'nodeMax'` |

Other options: `sampler` (`'trilinear'` default, or `'nearest'`), `isActive: false` to drop `vdbIsActive`,
`outside`: `'background'` (default, the tree's background value) or `'zero'` (the field is 0 outside the index bbox),
and `reader: 'lean'` (below).

## Majorants

Delta and ratio tracking need, along a ray, a bound of the density every sample can take. The `majorant` profile walks
one as a sequence of segments:

```wgsl
var it = vdbMajorantInit(g, oIdx, dIdx, tMin, tMax);   // index-space ray; d unnormalized, t is yours
loop {
    let s = vdbMajorantNext(&it);                      // (t0, t1, bound); t1 <= t0 ends the walk
    if s.y <= s.x { break; }
    // every vdbSample on [s.x, s.y) is <= s.z; with minima: >= vdbMajorantMinimum(&it)
}
```

Segments are contiguous and never empty. The bound is over the *sampled* field: a trilinear sample reads one voxel past
its cell, so a cell's bound covers its neighbours' first layer too. Three walks, picked by `majorant`:

| `majorant` | Walk | Data |
| --- | --- | --- |
| `'brick'` (default) | A 3D DDA over cells of `2^brickLog2` voxels (pmndrs/pathtracer's `ptDdaInit` / `ptDdaNext`) | `pool.setMajorant(id, vdbBrickMajorant(image))` from `@pmndrs/vdb/tools`; a grid without it walks as `'global'` |
| `'global'` | One segment over the sampler's support box | The grid's `valueMax` (also `vdbMajorantGlobal(g)`, the scalar a guiding or emission estimator needs) |
| `'nodeMax'` | The HDDA over the tree, leaf-sized cells widening over tiles | NanoVDB node stats (`HAS_MIN_MAX`); assumes inactive voxels don't exceed their leaf's max (fog) |

{/* snippet: majorant-host */}
```ts
import { VDBGridPool, vdbModuleEntries, vdbModuleWgsl, type VDBSlotModuleOptions } from '@pmndrs/vdb';
import { vdbBrickMajorant } from '@pmndrs/vdb/tools';

const pool = await VDBGridPool.create(device);
// Bounds over 8³ bricks for delta / ratio tracking, with minima for a residual tracker.
// outside: 'zero' matches the module below (a tap outside the grid's bbox reads 0).
const id = pool.add(smoke, { majorant: vdbBrickMajorant(smoke, { minima: true, outside: 'zero' }) });

const slot = { group: 2, firstBinding: 0 };
const options: VDBSlotModuleOptions = {
    slot,
    types: [...pool.types],
    profile: 'majorant', // sample + vdbMajorantInit / vdbMajorantNext
    majorant: 'brick',
    minima: true,
    outside: 'zero',
    reader: 'lean', // a fifth of the vendored accessor's size, same values
};
const module = vdbModuleWgsl(options);
const layout = device.createBindGroupLayout({ entries: vdbModuleEntries(slot) });
```

Build the bricks for the same `outside` as the module. Outside the walk's box the field is 0 with `outside: 'zero'`; with
`'background'` it is the tree's background, which the walk does not cover, so use a fog grid with background 0 there.
`vdbBrickMajorant(image, { align: 'pathtracer', resolution })` lays the cells out as the pathtracer's own
`brickMajorants` does for a dense grid at index `[0, n)` (cell c over `[8c − 1, 8c + 7)`), and gives the same arrays.

## The lean reader

`reader: 'lean'` swaps the audited PNanoVDB accessor for a compact descent with a one-leaf cache: `read` for Float is
3.1 KiB instead of 17.1, `sample` 5.1 KiB instead of 19.7. The functions and the values are the same (every scalar
type, both `outside` modes). It covers `read`, `sample` and `majorant` with `'brick'` or `'global'`; it has no march
layer, so no `march` profile, no `nodeMax`, and of the helpers only `rayClipSupport`. Use it when a kernel is near a
compiler's size limit.

## Helpers

Opt-in, and none is emitted unless listed:

| Helper | Profile | Function |
| --- | --- | --- |
| `cellBoundTrilinear` | `march` | `vdbCellBoundTrilinear(acc, ijk, dim)`: a bound for every trilinear sample whose base voxel is in that cell |
| `hddaCellEnd` | `march` | `vdbHddaCellEnd(&h)`: the ray `t` where the HDDA's current cell ends |
| `nodeAverage` | `march` | `vdbNodeAverage(acc, ijk, dim)`: the box mean of the aligned cell, from the node's stored average |
| `rayClipSupport` | `sample`+ | `vdbRayClipSupport(g, o, d, t)`: `vdbRayClip` against the sampler's support box |

When you skip empty cells with a bound, use `cellBoundTrilinear`, not `vdbNodeMax` alone. A trilinear tap reads one
voxel past its base voxel, into the neighbour cells.

## Grid types must match

The shader decodes only the types its module was generated for. A grid of any other type **reads as 0**. So a module
must be generated for every type the host may ever add: the known set, or `VDB_ALL_SCALAR_TYPES` (`float`, `fp4`,
`fp8`, `fp16`, `fpn`, `half`) to never rebuild a pipeline, at the price of the largest module. `pool.types` lists only the
grids present now. After each `add`, call `vdbCheckModule(pool, options)`: it throws `VDB_TYPE_NOT_COMPILED` or
`VDB_LAYOUT_MISMATCH`. It also takes just `{ types, layoutVersion? }`.

## Size budgets

The generated text has a size budget per profile and type set, checked in CI by `pnpm wgsl:size` (minified bytes, KiB
of 1024):

| Profile | Float only | One Fp type | Float + Fp8 + FpN |
| --- | ---: | ---: | ---: |
| `read` | 17.5 | 19 | 19.5 |
| `sample` | 21.5 | 23 | 24 |
| `march` | 29 | 30.5 | 31 |
| `majorant` (`brick`, `global`) | 23.5 | 25 | 26 |
| `majorant` (`nodeMax`) | 32 | 33.5 | 34 |
| `read`, `reader: 'lean'` | 4 | 5 | 6.5 |
| `sample`, `reader: 'lean'` | 5.5 | 6 | 6.5 |
| `majorant`, `reader: 'lean'` | 8.75 | 9 | 9.25 |

Helpers add 1 KiB to the profile's budget, and `nodeAverage` adds 1.5 KiB. The budgets exist because a path tracer's
kernels are already 41 to 55 KB of WGSL and compile time is on watch.
